# 设计令牌使用规范

> **唯一来源：`app.wxss` 顶部的「设计令牌」注释块。**
> 本文件只讲使用规则，色值以 `app.wxss` 为准；改色值请改 `app.wxss`，不要改这里。

## 为什么要有令牌

整改前同一语义散落着多个色值（4 种蓝、4 种标题深色、7 种次要灰、2 种页面背景），
导致「同一个意思在不同页面长得不一样」，且调主色要改十几个文件。
现已统一为 9 个令牌，全项目 WXSS 共 170 处引用。

| 令牌 | 色值 | 语义 | 对比度（白底） |
|------|------|------|----------------|
| `--brand` | `#2563eb` | 主色：按钮、链接、强调文字 | 5.17:1 ✅ |
| `--brand-light` | `#4f8bff` | 渐变亮端（只用在 `linear-gradient`） | — |
| `--brand-deep` | `#1d4ed8` | 浅蓝底上的蓝字（如认证徽章） | 在 `--brand-wash` 上 6.5:1 ✅ |
| `--brand-wash` | `#eef4ff` | 浅蓝底：标签、胶囊按钮 | — |
| `--ink-title` | `#0f172a` | 标题 | 18.6:1 ✅ |
| `--ink-body` | `#334155` | 正文（也是 `page` 默认色） | 10.4:1 ✅ |
| `--ink-muted` | `#64748b` | 次要/说明文字 | 4.76:1 ✅ |
| `--ink-disabled` | `#c7cdd8` | **仅禁用态**，禁止用于正文 | 1.7:1 ❌ |
| `--bg-page` | `#f5f7fb` | 页面背景 | — |

## 规则

1. **WXSS 里一律 `var(--令牌名)`，禁止再写死十六进制色。**
   ```css
   /* 好 */  .title { color: var(--ink-title); }
   /* 差 */  .title { color: #1f2937; }
   ```
2. **`--ink-disabled` 只能用在 `.xxx.disabled` / `[disabled]` 上**，
   它需要「看起来点不了」，做正文会读不清。
3. **`--brand-light` 只用于渐变**，不要单独当文字色（对比度不足）。
4. **渐变统一写法**：`linear-gradient(135deg, var(--brand), var(--brand-light))`。
5. **JS / `app.json` 不支持 CSS 变量**，只能写字面量，改动时记得同步。
   `app.json` 目前只有 4 个色值，已全部对齐令牌：

   | 位置 | 值 | 对应令牌 |
   |------|-----|---------|
   | `window.backgroundColor` | `#f5f7fb` | `--bg-page` |
   | `navigationBarBackgroundColor` | `#2563eb` | `--brand` |
   | `tabBar.selectedColor` | `#2563eb` | `--brand` |
   | `tabBar.color` | `#64748b` | `--ink-muted` |

   另：`pages/*/index.js` 里的 `confirmColor` 等也需手写同步。
6. 新增页面时不要自创灰阶，从表里挑最接近的一个。

## 批量替换工具

改动令牌后如需全项目重新收敛：

```bash
node .workbuddy/scripts/apply-design-tokens.js --check   # 只预览，不写文件
node .workbuddy/scripts/apply-design-tokens.js           # 执行替换
```

脚本会跳过 `--xxx: #fff;` 形式的令牌定义行，可重复执行（幂等）。
