# 小程序后台使用说明

> 手机上也能管数据了。**注意：在这个后台里改的就是云端数据，小程序立刻生效** ——
> 这一点和桌面后台完全不同，务必先看第六节。

配套文档：《[管理后台使用说明](./管理后台使用说明.md)》（桌面版，两边口径先读一遍再动手）

---

## 一、入口在哪

**小程序首页最底部**的公示区里，多了一个「**管理**」两个字。**只有管理员看得到**，
普通用户打开首页根本不会渲染这一项（服务端按 openid 判定，前端绕不过去）。

> ⚠️ **没开通之前，你自己也看不到这个入口** —— 它不是漏做的功能。
> 「必须是管理员才显示入口」和「得先拿到 openid 才能成为管理员」听起来绕不出来，
> 破局方法在第二节：后台页对非管理员也显示 openid，用开发者工具把它当成启动页直接打开即可。

点了之后进「后台管理」总览页。八个入口：

| 入口 | 干什么 |
|---|---|
| 公司 | 物流公司的增删改查 |
| 线路 | 出发地-目的地的增删改查 |
| 线路公司 | ★ 关联维护。**时效、是否直达、发车频率挂在这一层** |
| 公告栏 | ★ 首页顶部滚动播放的公告 |
| 优质线路 | ★ 首页「优质线路推广」卡片 |
| 纠错审核 | 用户提交的纠错，采纳 / 驳回 / 待定 |
| 批量导入 | 粘贴 CSV 批量导入公司 |
| 数据质量 | 缺电话多少家、多久没更新、有没有悬空数据 |

功能和桌面后台一一对应。

## 二、第一次开通（四步）

这个后台靠 **openid 白名单**认人，白名单写在云函数里，得手动走一趟。
**顺序不能乱**：云函数没部署时，`whoami` 取不到 openid，页面会显示「找不到后台服务」。

### 第 1 步：先把云函数 adminApi 传上去

whitelist 空着没关系（`whoami` 是唯一不校验管理员的接口，专门用来问「我是谁」）：

> 开发者工具 → 云开发 → 云函数 → 右键 **adminApi** → **上传并部署：云端安装依赖**

### 第 2 步：绕过隐藏入口，直接打开后台首页

后台首页有个特殊待遇 —— **对非管理员也显示 openid**（旁边有「复制」按钮），
就是专门留给这一步的：

> 开发者工具 → 工具栏「**编译模式**」下拉 → **添加编译模式** →
> 启动页面填 `pages/admin/index/index` → 确定

进去后页面会显示：

- 「后台还没有配置任何管理员」+ **一串 openid** —— 正常，这就是要找的东西
- 点「**复制 openid**」

### 第 3 步：把 openid 填进白名单

编辑 `cloudfunctions/adminApi/index.js` 顶部的 `ADMIN_OPENIDS`：

```
const ADMIN_OPENIDS = [
  'oXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXX'   ← 粘贴你的 openid
];
```

> ⚠️ **留着 `//` 的不算数。** 模板里的示例本来是注释形式，最常犯的错就是
> 「把示例行的内容改成了自己的 openid、却没删掉行首的 `//`」——
> 看着填好了，服务端眼里白名单还是空的。
> 填完用这条命令验：`node scripts/check-deploy.js` 会显示「已配置 N 个管理员」。

### 第 4 步：重新上传部署，之后入口就出来了

> 右键 **adminApi** → **上传并部署：云端安装依赖**

再回到首页（普通编译模式），底部公示区最后一个「**管理**」就出现了。

### 首页还是没有「管理」？按顺序自查

入口不显示 = **服务端还没认出你是管理员**，页面没坏。三个原因，逐个排除：

| 现象（打开后台首页时） | 原因 | 处理 |
|---|---|---|
| 「找不到后台服务」 | 云函数 adminApi 没传上去 | 走第 1 步重新上传部署 |
| 「后台还没有配置任何管理员」 | `ADMIN_OPENIDS` 是空的 | 走第 2~4 步 |
| 「你的微信号不在管理员白名单里」 | 填的是别人的 openid，或换号了 | 重新抄当前这个微信号的 openid |

> 注意改完云函数**必须重新上传部署**才生效 —— 只改本地文件、或者直接刷新模拟器都不管用。

> **白名单为空时，所有访问一律拒绝**（包括你自己）—— 这是有意为之的保守设计：
> 宁可后台不可用，也不能在没有配置的情况下放行任何人。

openid 在同一个小程序里是固定的，换手机、重装微信都不变。

## 三、手机上能做什么、不能做什么

| | 手机上 | 桌面后台 |
|---|---|---|
| 增删改查、审核 | ✅ 一样能改 | ✅ |
| 批量导入 | **粘贴 CSV 文本**（手机选不了文件） | **上传 xlsx / csv** |
| 时效改哪一页 | 一样：在线路公司那一层 | 一样 |
| 写到哪 | **云端（立刻生效）** | 本地副本（还要导入才生效） |

批量导入仍是「**预览 → 确认**」两步，**预览阶段一个字都不会写入**。
错误行会带行号，跳过不影响其他行。模板可以在页面里一键复制。

## 四、页面顶部的几种提示，都是什么意思

| 提示 | 含义 | 怎么处理 |
|---|---|---|
| 尚未配置管理员 | `ADMIN_OPENIDS` 还是空的 | 按第二节填 openid 再重新上传部署 |
| 你没有后台管理权限 | 你的 openid 不在白名单里 | 把页面显示的 openid 加进去 |
| 找不到后台服务 | 云函数 `adminApi` 没部署上去 | 回开发者工具上传部署 |

前两种属于「再试也没用」，页面不给重试按钮 —— 重试一百次也还是没权限。

## 五、两个后台放在一起比

| | 桌面后台 `admin/` | 小程序后台 |
|---|---|---|
| 写到哪 | **本地副本** `admin/data/*.json` | **直接写云端** |
| 多久生效 | 还要导出 + 控制台导入 | **立刻** |
| 缺点 | 慢，且副本会过期 | 手机屏幕小，批量操作不方便 |

---

## 六、★ 最重要的一条：别用本地副本覆盖云端

这是唯一一个能**成批抹掉运营数据**的操作，务必看懂这张图：

```
      ① 桌面后台这条路（会覆盖云端，慎用）
在后台改动  →  admin/data/*.json  →  export-seed 生成 .data/*.jsonl  →  控制台导入  →  云端被整表替换
   （本地）         （本地副本）              （中间文件）                          ↑ 小程序里改过的内容到这里全没了

      ② 小程序后台这条路（安全）
手机改动  →  云端  →  立刻生效，不存在半成品
```

⇒ **铁律：只要用小程序后台改过数据，就绝对不要再走第 ① 条路。**
那时候 `admin/data/` 已经是过期的旧数据，拿它去覆盖云端，等于把手机上改的东西整批删掉。

这条提示不只是写在文档里 —— 后台总览页**有一张常驻提醒卡**，不能顺手删。

> **例外：`export-seed.js --admin-only` 是安全的。**
> 它只重建桌面后台的本地副本，不产出要往云端导的 jsonl。日常把副本改乱了就用它恢复。

> ⚠️ 目前缺一个「**从云端导出到本地副本**」的脚本，所以现在还做不到
> 「用小程序改完 → 同步回桌面后台副本」。在它补齐之前，桌面副本重建后是 seed 基线数据。
