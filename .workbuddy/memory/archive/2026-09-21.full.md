## 🐛 BUG 修复：12 个 wxss 被写入 UTF-8 BOM 导致编译失败（同日）

**报错**：`./pages/agreement/index.wxss(1:1): unexpected '�' at pos 1`，小程序编译报 `unexpected \uFEFF`。

**根因**：v5.2 用 **PowerShell `Out-File` / `Set-Content` 默认编码**批量改写 wxss 时，Windows PowerShell 5.1 的默认编码是 **UTF-8 with BOM**，于是在文件头写入了 `EF BB BF`（U+FEFF）。WXSS 编译器不跳过 BOM，第 1 行第 1 列即报错。

**受影响**：12 个 `.wxss`，全部是 v5.2 批量正则改写过的文件：
`pages/{index,line-list,line-detail,favorite,user,contact,agreement}/index.wxss`、`pages/admin/{index,lines,line-edit,stats,ad-edit}/index.wxss`。
**未受影响**：`.js` / `.json` / `.wxml`（本轮未批量改写）、`app.wxss`（用 Write 工具写的，**无 BOM**）。

**修复**：PowerShell + `[System.IO.File]::ReadAllBytes` → 判断前三字节 → 用 `WriteAllBytes` 写回 `bytes[3..]`（**不能**用 `Set-Content`，会再次加 BOM）。
- 备份：`.workbuddy/backup-bom-20260921/`（12 个原始带 BOM 副本，扁平化命名）
- 清理后首字节 `2F 2A`（=`/*`），中文正常解码，122 个源文件 BOM 归零
- 8 回归测试全通过；静态体检通过（16 页面 wxml、路由 14、tabBar 3，绑定 88 / data-* 41 / 跳转 23 / wx:for 18，无问题）

**⚠️ 永久护栏（重要）**：**改 Windows 上的 wxss/wxml/js/json，禁止用 `Out-File`/`Set-Content`/`>` 重定向**（默认带 BOM）。必须用：
- **Write / Edit 工具**（推荐，写成无 BOM UTF-8）
- 或 `[System.IO.File]::WriteAllText($path, $text, (New-Object System.Text.UTF8Encoding($false)))`
- 或 `WriteAllBytes` 直接写字节

**提交前自检**（一行扫全项目 BOM）：

### 管理后台（PRD 模块 06）· 零依赖
- 只用 Node 内置模块（http/fs/crypto/zlib），**无 package.json、无 node_modules**
- server.js（HTTP）+ lib/ 七个模块：store（纯内存业务）/ db（只读写 JSON）/ repository（写穿透）/ auth（scrypt+定长比较+HttpOnly）/ importer（手写 xlsx/csv 解析）/ api / views（服务端渲染）
- 启动：node admin/server.js → http://127.0.0.1:8787 ，默认 admin / admin12345
- **只绑 127.0.0.1**：后台是唯一写入口，必须关门
- 零依赖 xlsx 解析：xlsx 是 zip，用**中央目录**定位 + zlib.inflateRawSync 解 deflate
- multipart 二进制保真：readBody 同时给 raw(utf8) 与 rawBinary(latin1)，文件走 latin1 无损往返

### ★★ 本段最重要的事故与修复：覆盖写护栏
