## ★★ 云控制台不认 .jsonl（commit `1d20156`）

用户按清单导 `.data/*.jsonl` 被拒：
`Database Import Fail: invalid import filename(only support .json or .csv)` returnCode=11050。

**项目一直存在的隐性错误**：部署文档多年写着「导入 .data/*.jsonl」，而控制台只认两种扩展名 ——
文档、脚本、平台能力三者不一致，照着做必然失败（之前从没真正执行过这一步，所以没暴露）。

**处理**
1. 新增 `scripts/export-cloud-import.js`：把 6 个 jsonl 转成 `.data/import/*.json`。
   **内容是 JSON 数组**（不是只改后缀）—— JSON Lines 能否被识别不明确，数组是官方文档形态，最稳
2. ★★ **必须保留 `_id`**：route_companies 靠 routeId/companyId 引用另两张表的主键，
   控制台自动生成 _id ⇒ **所有关联变悬空外键**。导入时冲突处理必须选 **Insert**
3. 新增 `test/suites/cloud-import.test.js`（7 断言）：无 BOM / 是 JSON 数组 / 条数 40·55·72·344·4·6 /
   每条有 _id / **关联表引用的 key 在目标表里真实存在** / 文档口径与实际一致
4. 文档口径同步：不再写「导 jsonl」，改为「先跑脚本生成 .json 再导」+ 两条 ⚠️

**最终正确形态（★ 记住这两个条件缺一不可）**

| 组合 | 结果 |
|---|---|
| JSON Lines 内容 + `.jsonl` 扩展名 | ❌ `invalid import filename(only support .json or .csv)` |
| JSON 数组 `[...]` + `.json` 扩展名 | ❌ `导入数据格式不正确，请检查是否为 JSON Lines 格式` |
| **JSON Lines 内容 + `.json` 扩展名** | ✅ |

第一次自己判断「JSON 数组是官方文档形态最稳」是**错的**，实际报错文案直接点名要 JSON Lines。
⇒ 脚本改为原样保留每行一条（只换扩展名），注释里把这张对照表写死，测试断言首字符 `{` + 行数=条数。

**12 套件 520 断言全绿**；`.data/import/` 是本地产物不入库（`.data/` 已在 .gitignore）
