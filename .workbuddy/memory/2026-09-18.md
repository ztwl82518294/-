## 修复：乡镇级目的地查不到（报障「济南→羊流镇」无法查询）

**现象**：管理端存在「济南-羊流专线：济南市 → 羊流镇」，但 C 端无论搜「羊流」还是选地区都查不到。

**根因**：`searchLine` 匹配线路城市字段时用 `norm()` 后**严格相等**比较，`norm` 只剥 市/区/县/省/自治州/盟，
不剥镇/乡/街道，于是「羊流」≠「羊流镇」直接漏单。用 Node 复刻判定逻辑验证：只有输入完整「羊流镇」才命中，
输入「羊流」「洋流镇」、或用地区选择器选 泰安/新泰 全部落空。

**改动**（2 个文件，仅在 searchLine 云函数内）：
- `cloudfunctions/searchLine/placeMatch.js`：新增 `SUB_CITY_SUFFIX`（镇/乡/街道/办事处/村）、
  `TOWN_ALIAS`（洋流→羊流，同音错写归一）、`cityCore()`（剥离末级后缀，剥离后须 ≥2 字）、
  `sameCity()`（归一化相等或 cityCore 相等），均已导出。
- `cloudfunctions/searchLine/index.js`：直达与中转的城市字段比对全部换成 `sameCity`/`cityCore`；
  中转分组键 `firstDests/secondOrigins` 也改用 `cityCore`，避免「羊流镇 ↔ 羊流」中转链断裂。

**关键护栏（踩坑记录）**：
- 绝不能直接改 `norm()` 去剥「镇」——「景德镇市」会被削成「景德」，regionData 的
  `PREFECTURE_KEYS`/`isParentCity` 立即断链。故只在城市字段比对层做容错，regionData 归属判定仍走 `norm`。
- 单字仍走精确相等，不做包含匹配（防「陵」误命中「乐陵」）。

**新增测试**（Node 可直接跑）：
- `.workbuddy/scripts/test-place-match.js`（18 项：报障场景 + 反例 + 原口径回归）
- `.workbuddy/scripts/test-searchline.js`（扩到 15 项，新增 mock DB 端到端乡镇级用例）
- 运行：`node .workbuddy/scripts/test-searchline.js`（用 managed node 绝对路径）

**待用户操作**：searchLine 云函数需在开发者工具重新上传部署。

**遗留（非代码可解）**：regionData 只到区县级，无乡镇归属数据，因此「选新泰市/泰安市」这类
上级城市查询仍不会带出「羊流镇」线路。运营侧解法：给该线路的「目的辐射区 toAreas」补上上级县市
（如填「新泰」），走 contains 辐射区路径即可命中并显示「济南市 → 羊流镇 → 新泰市」。

## 全项目逻辑审阅 + 缺陷修复（第二轮，同日）

**审阅方法**：① 静态体检脚本扫 16 个页面的 wxml 事件绑定 / dataset 字段 / 路由跳转；
② 人工过搜索、收藏、VIP、统计兑奖、管理端（含 11 个云函数）六条链路。

### 修复的缺陷（P0）
1. **老数据缺 `id` 字段导致三条链路断裂**（本日主 bug）
   - 症状：搜索结果点卡片 → 详情页 `Number(undefined)=NaN` → 「链接已失效」（线路明明存在）；
     收藏 → `addFavorite` 因缺 id 直接 reject →「操作失败」；管理端「编辑」→ `where({id:NaN})` →「未找到该专线」。
   - 根因：`id` 是业务字段（毫秒时间戳），旧版批量导入/控制台直灌未写入；而分享链接、
     列表跳转、收藏、编辑全部只认 `id`，`_id`（真主键）反而没人用。searchLine 内部早已用 `_id||id` 兜底，
     前端却完全没有 —— 服务端知道有这个坑，前端不知道。
   - 修复：新增 `utils/lineKey.js`（`parseLineKey/lineWhere/lineRef`）统一双键兼容；
     详情页、管理端编辑页、广告关联三处 `where({id})` 全部改走 lineKey；
     `searchLine.normalizeLine` 补 `id = _id`；`storage.addFavorite` 用 `id || _id`；
     列表/中转卡片跳转键改 `_id`；`adminLine` 新增 `healMissingIds()` 自愈（列第 1 页顺带跑，
     另有 `action: 'healIds'` 手动触发）。

2. **`wx:key="id"` 在多条记录缺 id 时会冲突** → 列表 `wx:key` 改 `_id`。

### 修复的缺陷（P1）
3. **`pickFields` 局部更新清空城市索引**：无条件 `out.fromCity = normCity(out.fromCityName)`，
   未提交城市名时会写入 `''` 覆盖既有索引，该线路从所有搜索里消失。改为「带了城市名才派生」。
4. **管理端无法录入乡镇级目的地**：城市字段只有 `picker mode="region"`（级联到区县），
   而数据里存在「羊流镇」这类乡镇 —— 界面录不进、也改不了。改为「手输 input + 选择按钮」。
5. **`batchVip` 只处理前 1000 条**：公司线路超 1000 条时续费静默漏掉。改为 skip 分页（上限 2 万）。
6. **下架线路仍可访问**：详情页不校验 `status`，旧分享链接/收藏入口能打开已下架线路并显示电话。
   改为 `status === 0` 直接提示「该专线已下架」。
7. **statLog 单日埋点上限 30 条过紧**：一次搜索会产生 1 条 search + 若干条 view，
   重度用户几十条就封顶，而月度榜单按事件总数排名 —— 变相惩罚活跃用户、榜单失真。提到 100。
8. **广告关联专线 `Number(lineId)` 强转**：_id 字符串会被转成 `NaN→0`，关联失效。改为数字/字符串双保留。
