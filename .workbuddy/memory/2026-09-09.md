## 万股级架构改造（阶段一，S1）

背景：用户计划扩充至上万条物流专线，旧架构（全量拉取内存过滤/单页 limit 1000）会漏单且性能差。

- S1-1 地名规范化：adminLine save/batchSave 服务端派生 `fromCity`/`toCity` 标准城市字段（norm 去后缀），不信任客户端传值；旧数据由查询兼容。
- S1-2 searchLine 两级查询：用户输入经 getCityLevel 映射标准城市 → 数据库粗过滤（fromCity 精确 + fromCityName 后缀变体 $in 兼容旧数据 + 辐射区正则）→ 内存精过滤（原有模糊匹配能力不变）。中转搜索同步改造（_.or 组合查询）。
- S1-3 管理端列表真分页：adminLine list 改 page/pageSize/keyword 服务端正则搜索（id desc，新线路在前；自愈迁移仅第 1 页执行）；管理页滚动翻页 + 已加载/总数指示；导入改分批 200 条带进度。
- S1-4 索引与模板：lines 索引清单新增 fromCity_1/toCity_1/fromCity_status；新增 docs/专线导入模板.json + docs/批量导入说明.md。
- 测试：.workbuddy/scripts/test-searchline.js（mock wx-server-sdk）9 项断言全过（新字段查询、旧数据兼容、区县归属、VIP 置顶、边界）。
- 部署提醒：需上传 adminLine、searchLine；控制台补 3 条新索引（fromCity、toCity、fromCity+status）。
- 导出功能注意：万股级下云函数响应有大小限制，导出仅覆盖已加载页（已在代码注明）。
