## 意外收获：修好一个形同虚设的检查工具

清理中实跑 `check-requires.js`，发现它**长期报假失败**（把注释里的用法示例当真实依赖）：

```
❌ test\framework.js:12  ->  ../framework
```
（第 12 行是注释 `* 在套件里：const { ... } = require('../framework');`）

**假失败比不检查更糟** —— 会让人直接忽略整个检查。修复：加 `stripComments()`，
**剥注释但保留字符串**（`require` 的路径就在字符串里），且**用等长空白替换 → 行号不变**。

> 扫描形同虚设。**剥注释绝不能连字符串一起剥。**

### 推送过程：撞上一次「远程已有提交」
用户建仓时勾了 README，远程先有一个 `Initial commit`（仅 14 字节占位 README `# -`），
`git push` 被 `! [rejected] (fetch first)` 拒。处理：
1. `git fetch --no-tags origin <SHA>` 按 SHA 拉下来（普通 `git fetch` 在本环境不落 ref，见下）
2. `git merge FETCH_HEAD --allow-unrelated-histories`（无共同祖先，必须加这个参数）
3. README 是 `add/add` 冲突，远程只有 14 字节占位 → **取 ours**（本地 6.4KB 完整文档）
4. 合并提交 + 推送 → `6623834..615a68d  main -> main` ✅

### ★ 本机 git 的怪毛病：远程跟踪引用存不住
`git fetch` 报「new branch」，但 `refs/remotes/origin/*` **不落盘**；
`git update-ref refs/remotes/origin/main <SHA>` **返回 0 却什么也不写**（`git show-ref` 里没有），
`.git/refs/remotes` 始终是空目录。⇒ `git status` 会显示 `[origin/main: gone]`、`git log origin/main` 报
`Not a valid object name`。**这是沙箱对 `.git` 写入的限制，不是仓库坏了。**
- **别被 `[gone]` 吓到**：判断「有没有推上去」只看 `git ls-remote origin`（问服务端），
  或直接用 commit SHA 查（`git ls-tree -r <SHA>`）。
- 要比较远程内容时，用 `git fetch --no-tags origin <SHA>` 再对 `FETCH_HEAD` 操作。

### 为什么写成脚本（两处环境坑）
1. **Git Bash 的 PATH 已损坏**（`env`/`grep`/`ls` 全 `command not found`）→
   无法用 `export https_proxy=...`，改用**仓库级** `git config http.proxy`（不设全局）。
2. **Node 的 `execSync` 在 Windows 上走 `cmd.exe` 而非 bash** →
   `git remote get-url origin 2>/dev/null || true` 报「'true' 不是内部或外部命令」并**整脚本崩掉**。
   探测型调用一律 `try/catch`（脚本里封装成 `trySh()`），**别写 POSIX 兜底语法**。

### 写这个检查脚本时踩的两个坑（都是**自己写的脚本误报**）
1. **`collection()` 的参数常常是常量引用** —— 云函数里写的是 `.collection(COLLECTION)`
   （`COLLECTION` 是文件顶部常量）。只匹配字符串字面量会**一处都找不到**，误报「未发现 collection()」。
   ⇒ 要先把同文件里的 `const XXX = '值'` 收集起来，再解析 `collection(IDENT)`。
2. **`view_dedup` 是 `trackCompanyView` 的内部去重表**，不在「六表模型」里、不进 `shared/schema.js`。
   第一次写成「只在日志里提一句例外」，但**校验没真豁免**，照样报错。
   ⇒ 用显式的 `INTERNAL_COLLECTIONS` 集合豁免，**别只在注释里说明**。

> 教训：**自检脚本报错时，先确认是真的代码错、还是断言/检查逻辑错。**
> 本次两条都是检查器自己的问题，代码没问题。这与「修测试而不是修功能」是同一个原则。
