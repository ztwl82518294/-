### ★ 本机 git 的怪毛病：远程跟踪引用存不住
`git fetch` 报「new branch」，但 `refs/remotes/origin/*` **不落盘**；
`git update-ref refs/remotes/origin/main <SHA>` **返回 0 却什么也不写**（`git show-ref` 里没有），
`.git/refs/remotes` 始终是空目录。⇒ `git status` 会显示 `[origin/main: gone]`、`git log origin/main` 报
`Not a valid object name`。**这是沙箱对 `.git` 写入的限制，不是仓库坏了。**
- **别被 `[gone]` 吓到**：判断「有没有推上去」只看 `git ls-remote origin`（问服务端），
  或直接用 commit SHA 查（`git ls-tree -r <SHA>`）。
- 要比较远程内容时，用 `git fetch --no-tags origin <SHA>` 再对 `FETCH_HEAD` 操作。

### 问题 1：首页所有按钮点击没反应（根因：隐形遮罩）

因果链（已完整验证）：
1. `components/privacy-modal/index.json` 是 `styleIsolation: "isolated"`
   ⇒ **`app.wxss` 的全局 `.mask` 进不来**
2. `privacy-modal/index.wxss` **漏写 `.mask`** ⇒ 遮罩零尺寸、零背景，**视觉上完全看不见**
3. `onReject()` **没有 `setData({ visible: false })`** ⇒ 用户点「不同意」后，
   `.pm-root`（`position:fixed; inset:0; z-index:1000`）**永久留在 DOM 里覆盖整屏**
4. ⇒ 首页所有按钮的点击被它吃掉

**为什么症状是「有时好有时坏」**：取决于用户当初点的是「同意」还是「不同意」——
点同意会关弹窗，一切正常；点不同意则遮罩永驻，整页失灵。

修复 4 处：
- `privacy-modal/index.wxss` 补 `.mask`（`position:absolute; inset:0; background:rgba(15,15,15,.6)`）
- `privacy-modal/index.js` 的 `onReject()` 加 `this.setData({ visible: false })`
- `privacy-modal/index.wxml` 遮罩 `bindtap="noop"` → `bindtap="onReject"`（多一层保险，点遮罩即关）
- `components/city-picker/index.wxss` **同款缺陷一并修**（同样 isolated + 同样漏 `.mask`）

> **立为规则**：组件内遮罩/弹层样式一律自备，**不要依赖 `app.wxss` 的全局 `.mask`**。
> 排查「按钮没反应」的顺序：透明遮罩 → bindtap 笔误 → 跳转目标未注册 → 被覆盖 → catchtap 截断。

## 「红框内如何换行」（网点行交互补齐）

用户发后台「公司编辑」页截图，框住发站/到站的「地址 + 电话」一行，问怎么换行。

**根因两个**：① 网点行是**纯 input**，没有加行按钮 —— 提示写着「一行一个网点，最多 10 个」，
后端也支持 `departure_address_0..9`，但界面上**没有任何办法加第二行**；
② 表单里有 submit 按钮，在 input 里按 Enter 的浏览器默认行为是**提交整张表单**，
用户想换行，结果页面直接保存跳走。

**修法**（views.js stationBlock + admin.css + admin.js initStationBlocks）：
- 区块加「＋ 添加网点」按钮（`data-add-station`），每行加「×」删除（`data-del-station`，剩一行时删=清空）
- **网点行里按 Enter = 换行**：非最后一行聚焦下一行地址框；最后一行且有内容就新增一行；
  `keydown` 上先 `preventDefault()` 拦掉隐式提交
- 增删行后 **renumber**：后端按 `prefix_address_0..9` 索引收集，删中间行留索引洞，
  行数一多会越过 9 丢数据 —— 重排最稳
- 模板与 JS 的交互契约用 data-* 标记（data-station-row / data-station-field / data-station-block），
  注释里写明「两边要一起改」；admin.test.js + smoke-admin 各加断言钉住
- 窄屏 CSS：地址占满一行，电话 + × 挤第二行

教训：**「提示文案承诺了交互，页面却没给交互」是死按钮的另一种形态** ——
和公告外链「点了没反应」同源。文案说「一行一个」，就得真有办法加一行。

### 追加：用户反馈「刷新后还是不能换行」——两层缓存

代码是对的（起全新进程登录验证：admin.js 含 initStationBlocks、编辑页含
data-add-station / data-station-row / data-del-station，全 ✓），但用户刷新看不到，

1. **进程没重启**：`views.js` 是启动时 require 进内存的，改了模板**必须重启进程**，

2. **浏览器缓存旧 admin.js**：`serveStatic` 没带 `Cache-Control`，

- `serveStatic` 静态资源一律 `Cache-Control: no-store`（后台单机自用，缓存没收益）
- `start-admin.js` 端口已占用时**明说**：那是旧进程，要先关黑窗口再重新双击 + Ctrl+F5
- `docs/管理后台使用说明.md` 新增「改了后台却不生效怎么办」一节
- smoke 加 3 条断言（css/js 的 no-store + 已有静态资源可访问）

> 教训：**「改了代码没生效」类问题，先分清是进程缓存还是浏览器缓存**，
